## 二、建议补的文档

### 1.【推荐补】独立的"修改说明"（题面明确点名）

- **问题**：题面要求"修改说明、注明复用项目/组件与自己的改动"。当前复用/改动信息只有 README 第 6 节一段话，细节要靠翻 git log；面试官拿到压缩包不一定会翻 git。
- **建议**：新增一个简短 `CHANGELOG.md`（或在 README 里把"修改说明"做成独立小节），逐模块列清：
  - **复用**：早期 config/clock/database/models 骨架；FastAPI、SQLAlchemy、Uvicorn、pytest、httpx、tzdata 等免费组件；
  - **新增/改动**：12 张表、重复/退款检测、状态机、提醒调度、模拟通知四态、后台线程、demo、单页前端、各自的测试；
  - 可按 git 提交顺序列（每个 commit 做了什么）。
- **理由**：题面白纸黑字要求，且成本很低（十几分钟）。

### 2.【建议补】"必要测试数据"说明

- **问题**：题面要求"必要测试数据"。当前数据由 demo.py / pytest 运行时动态生成，没有独立的种子数据文件，也没有一段明确说明"会生成哪些虚构数据"。`data/swagger-demo.db` 是手动 Swagger 操作留下的库，不是结构化测试数据。
- **建议**：在 README 补一小段"测试数据说明"——
  - demo.py 自动生成哪些虚构用户/交易/退款/到账；
  - 页面 Demo Lab 各按钮会生成什么；
  - （可选）提供一个 `seed.py` 一键灌入固定演示数据。
- **理由**：让"测试数据"可定位、可复现，成本低。
